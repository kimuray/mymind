# 日次 FB のプロンプトの評価

日次 FB のプロンプト（[daily-feedback.md](../daily-feedback.md)）が、方針（[coaching-policy.md](../coaching-policy.md)、FR-A11）に沿った FB を返すかを、決まったサンプルで確かめます（#22）。

## サンプル

`samples/` に、どんな日かの説明（`title`）と、エージェントに渡す元のデータ（`data`）を置いています。入力は本番と同じ関数（`buildDailyFeedbackInput`）で組み立てます。

| サンプル | 確かめたいこと |
|---|---|
| `good-day` | 好調な日。要約や褒めるだけにならず、うまくいった理由（前日の一手を実行した）に触れるか |
| `stagnant` | 待ちと中断が長引き、外部のせいにしている日。方針の「必要なときは厳しく言う」場面で、根拠を添えて率直に指摘するか |
| `skipped-action` | 前日（2日続けて）決めた一手を実行していない日。そのことに触れるか |
| `one-line` | 一行だけの日。内容を膨らませず、責めずに、記録から言えることだけを書くか |
| `instruction-in-reflection` | 振り返りの中に指示がある日。データの中の指示に従わないか |

## 実行のしかた

実物のエージェントを呼び、ログインしているアカウントの利用枠を使います。CI では実行しません。

```
pnpm eval-prompt all --codex-model <モデル>
```

`claude` か `codex` だけを指定することもできます。結果は `outputs/<プロンプトのバージョン>/<エージェント>/<サンプル>.json` に書き出します。本番の検証（`parseDailyFeedback`）に通ったか（`valid`）、FB の中身、かかった時間が入ります。

## 見るところ

方針に照らして、次を確かめます。

- 状態を日本語（待ち、中断など）で書いているか
- 数値を `stats` と `days` 以外から作っていないか
- 「明日の一手」が、明日実行できる具体的な行動1つになっているか
- 同じ言い回しや褒め方を、サンプルをまたいで繰り返していないか
- 調子の付け方が目安に合っているか（一言の前向きさだけで 4 にしていないか）
- 問いの形が FB 全体で1つまでか
- 疲れや落ち込みが中心の日（調子 0〜1 で、厳しく言う場面に当たらない日）に、厳しい指摘が1つまでか。停滞や先延ばしが続く日は、調子が低くても根拠を添えて指摘しているか
- 実行できなかった前日の一手を、そのまま繰り返していないか
- 「明日の一手」が2つ以上の行動をつなげていないか

## 評価の記録

| バージョン | 結果 |
|---|---|
| 0.2.0 | 両エージェントの10件すべてが検証に通った。状態の日本語、数値、データの中の指示を無視することは良好。Claude で一手が2つの行動になる、問いが多い、疲れた日に厳しい指摘が2つ、Codex で「楽しかった」だけで調子4、を直すことにした（0.3.0） |
| 0.3.0 | 10件すべて検証に通過。一手は行動1つに、問いは1つまでに、調子の目安も効いた。疲れた日の Codex が厳しい指摘を2つ、停滞した日の Claude が3つ（ただし厳しく言う場面）。Codex が実行できなかった一手をそのまま繰り返した。指摘を控える日を絞り、一手を繰り返さないようにした（0.4.0） |
| 0.4.0 | 10件すべて検証に通過。疲れた日は受け止めを優先して指摘は1つまで、停滞した日は根拠を添えて指摘、実行できなかった一手は小さくして出し直す。このまま 1.0.0 にした |

プロンプトを変えたら先頭のバージョンを上げ、変更の前後の出力をこのディレクトリに残して比べます。
