# アーキテクチャのルール

## 依存の方向

パッケージ間の依存は次の方向だけを許可します。`pnpm deps:check`（dependency-cruiser）で検証し、違反すると CI が失敗します。

```
domain  ←  db, agent  ←  server
domain  ←  web
```

`packages/domain` は、他のパッケージ、Node.js の組み込みモジュール、DB や HTTP のライブラリに依存しません。`apps/web` は `apps/server` のコードを直接読み込まず、Hono RPC の型だけを共有します。

## 状態の変更

タスクのステータス変更と計画への出し入れは、必ず `packages/domain` の関数に現在の状態と操作を渡し、返ってきたイベントを `packages/db` のリポジトリで保存します。イベントの追加と `tasks.status` の更新は、同じトランザクションで行います。サーバーのハンドラや画面から `tasks.status` を直接書き換えません（ADR-0004）。

## エージェント

エージェントの起動は `packages/agent` の `AgentRunner` インターフェースを経由させます。サーバーのコードから `child_process` を直接使いません。エージェントに渡す入力は `packages/agent` で組み立て、数値は `packages/domain` の集計関数で計算した値を使います。出力は必ずスキーマで検証します（ADR-0003）。

## セキュリティ

サーバーは `127.0.0.1` だけで待ち受けます。状態を変更するエンドポイントを追加するときは、Host・Origin の検証とセッショントークンの確認を行うミドルウェアの内側に置きます。Markdown を HTML に変換して表示するときは、生の HTML を無効にし、サニタイズを通します。

## データの場所

実データは `~/.mymind/`（DB、バックアップ、ログ）に置きます。開発とテストでは環境変数 `MYMIND_DATA_DIR` で `./.data` などに切り替え、実データに触れません。
