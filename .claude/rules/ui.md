# UI のルール

## 参照するデザイン

画面を実装する前に、Figma「mymind view design」の該当フレームを `get_design_context` で確認します。フレーム名と手順は `docs/design/README.md` を見てください。Figma に接続できない場合は `docs/design/mockup-source/` を参照します。

## デザイントークン

色、角の丸み、余白、書体、ガラスの表現は、`DESIGN.md` で定義したトークン（CSS 変数）だけを使います。コンポーネントの中に `#2F4B7C` や `rgba(...)` を直書きしません。トークンの定義は `apps/web/src/styles/tokens.css` に置き、`pnpm design:check` でそれ以外のファイルにある色の直書きを検出します。新しい値が必要になったら、先に `DESIGN.md` と `tokens.css` に追加します。

## コンポーネント

マメは必ず `Mame` コンポーネント（`mood` と `size`）を使います。ステータスアイコン、バッジ、ボタン、`kbd` も共通コンポーネントを使い、画面ごとに作り直しません。

## キーボード操作

キーの割り当ては、キーマップの定義ファイル1か所で管理します。新しいショートカットは定義ファイルに追加し、`DESIGN.md` のキーマップ表も同時に更新します。コマンドパレットとショートカット一覧はこの定義から生成するので、個別に追加しません。入力欄にフォーカスがあるときは、修飾キーなしのショートカットが発火しないようにします。

## アクセシビリティ

操作できる要素は、実際の `button`、`a`、`input` で作ります。アイコンだけのボタンには `aria-label` を付けます。キーボードフォーカスは常に見えるようにします。文字色は `--ink-4` より薄くしません。FB の生成状態のように非同期で変わる領域には `aria-live="polite"` を付けます。

## パフォーマンス

`backdrop-filter` はリストの各行に使わず、行を包む外側の面にだけ使います。タスクの操作は TanStack Query の楽観的更新で即時に画面へ反映します。
