## 背景

ADR-0006。node:sqlite を第一候補にしているが、drizzle-kit はDB接続を伴うコマンドで node:sqlite に未対応との報告がある。

## やること

- [x] `drizzle-kit generate` でSQLを生成し、実行時に drizzle-orm のマイグレーターで適用できるか確かめる
- [x] WAL、busy_timeout、`VACUUM INTO` が使えるか確かめる
- [x] Vitest でインメモリDBを使ったテストが動くか確かめる
- [x] 結果に応じて `packages/db` の雛形を作る

## 完了条件

- ADR-0006 を「採用」に更新している
- better-sqlite3 を選んだ場合は、`pnpm-workspace.yaml` のビルド許可とサンドボックスの通信先が更新され、クリーンな環境で `pnpm install && pnpm test` が通る

NFR-04、ADR-0006

## 作業の記録

### 2026-09-23 計画

- Node 24.21.0（SQLite 3.53.4）で `node:sqlite` 単体を確認したところ、WAL、`busy_timeout`、`VACUUM INTO`、インメモリ DB はいずれも使えた
- `drizzle-orm/node-sqlite` は 1.0 系のプレリリースにしかなく、安定版 0.45.3 には含まれない。Yoshihiro の判断で、drizzle-orm / drizzle-kit を 1.0.0-rc.4 に完全固定して検証する
- `packages/db` の雛形を作り、次を Vitest の結合テスト（`NFR-04`）で確かめる
  - `drizzle-kit generate` で生成した SQL を、実行時に drizzle-orm のマイグレーターで適用できる
  - 接続を開くときに WAL、`busy_timeout`、外部キーを設定できる
  - `VACUUM INTO` で別の場所にスナップショットを書き出し、開いて読める
  - Drizzle のトランザクションで、途中の失敗がロールバックされる（ADR-0004 の前提）
- 結果を ADR-0006 に反映する

### 2026-09-23 結果

- node:sqlite を採用した。検証の結果と追加の決定は ADR-0011 に記録し、ADR-0006 のステータスを「採用」にした
- `drizzle-orm/node-sqlite` の `transaction()` はコールバックを同期的に呼ぶ。非同期のコールバックでは最初の `await` の前にコミットされ、ロールバックされない。型が非同期のコールバックを拒否するので、トランザクションは同期で書き、`.run()` / `.all()` / `.get()` を使う
- `packages/db` に `openDatabase`（PRAGMA の設定とマイグレーションの適用）と `writeSnapshot`（`VACUUM INTO`）を置いた。アプリのテーブルは issue 018 で追加する
- better-sqlite3 は使わないので、`pnpm-workspace.yaml` のビルド許可とサンドボックスの通信先の変更は不要。esbuild（drizzle-kit の依存）のビルドスクリプトは無視されたままだが、`drizzle-kit generate` は動いた
