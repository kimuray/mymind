# ADR-0011：node:sqlite を採用し、Drizzle は 1.0 の rc に固定して同期のトランザクションで使う

- ステータス：採用
- 日付：2026-09-23

## 背景

ADR-0006 で第一候補にした `node:sqlite` を、issue 002 のスパイクで検証しました。検証の環境は Node 24.21.0（組み込みの SQLite 3.53.4）です。

`node:sqlite` 単体では、ADR-0006 で確かめるとした機能はすべて使えました。

| 確かめたこと | 結果 |
|---|---|
| WAL モード | 使える（`PRAGMA journal_mode = WAL`） |
| `busy_timeout` | 使える（`DatabaseSync` の `timeout`。別の接続が書き込み中なら待ったあとで `database is locked` を返す） |
| `VACUUM INTO` | 使える。書き出したファイルは別に開いて読める |
| インメモリ DB での Vitest | 動く。実験的機能の警告も出ない |
| `drizzle-kit generate` | DB に接続せずに SQL を生成できる。ドライバの指定は不要 |
| drizzle-orm のマイグレーター | 生成した SQL を開くときに適用でき、開き直しても繰り返さない |

一方で、ADR-0006 の比較表で「対応」としていた `drizzle-orm/node-sqlite` は、1.0 系のプレリリース（`1.0.0-rc.4`、2026-06 公開）にしかなく、安定版（0.45.3）には含まれていませんでした。また、このドライバは同期の `DatabaseSync` を包んでおり、`transaction()` はコールバックを同期的に呼んで、戻り値を待たずにコミットします。非同期のコールバックを渡すと、最初の `await` の前にコミットされ、後で例外を投げてもロールバックされません。

## 決定

**`node:sqlite` を採用する。** ネイティブモジュールを使わず、インストールと Node の更新を単純に保ちます。

**drizzle-orm と drizzle-kit を 1.0 の rc に完全に固定する。** `packages/db` の `package.json` では、範囲指定（`^`）を使わずに `1.0.0-rc.4` と書きます。rc の間の更新は、`packages/db` のテストが通ることを確かめてから、両方を同じバージョンに上げます。1.0 の正式版が出たら、正式版に上げます。

**トランザクションは同期で書く。** `db.transaction()` のコールバックは同期関数にし、中のクエリは `await` ではなく `.run()` / `.all()` / `.get()` で実行します。非同期のコールバックは Drizzle の型が拒否するので、`pnpm typecheck` で検出できます。この誤用がロールバックされないことは、`@ts-expect-error` を付けたテストで記録しておき、型のガードがなくなったら気づけるようにします。トランザクションの外では、`await` で書いてかまいません。

**接続を開くときの設定は `openDatabase` に集める。** WAL、`busy_timeout`（既定は5秒）、外部キーの有効化、`synchronous = NORMAL` を設定してから、マイグレーションを適用します。

**スナップショットは `VACUUM INTO` で書き出す（NFR-04）。** 書き出し先が既にある場合は上書きせずに失敗を返します。

## 結果

ADR-0004 の「イベントの追加と `tasks.status` の更新を同じトランザクションで行う」は、同期のトランザクションで満たせます。リポジトリ層の書き込みは、同期の関数として書くことになります。同期で動くため、1つの接続の上でトランザクション同士が混ざることはありません。一方で、トランザクションの中でエージェントの呼び出しなどの非同期処理を待つことはできないので、必要な値を先に揃えてからトランザクションを始めます。

プレリリースに依存するため、rc の間に破壊的な変更が入る可能性があります。影響は `packages/db` のリポジトリ層に閉じ込めます。1.0 の正式版が出るまでに、Drizzle の対応状況が期待と異なる方向に変わった場合は、better-sqlite3 と Drizzle の安定版に切り替えることを、新しい ADR で検討します。
