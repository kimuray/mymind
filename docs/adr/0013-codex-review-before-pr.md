# ADR-0013：PR を作る前に、Codex に差分をレビューしてもらう

- ステータス：採用
- 日付：2026-10-04

## 背景

mymind の開発では、Claude Code が issue の実装から PR の作成までを行い、自律モードでは人の確認を待たずにマージまで進めます（`.claude/rules/autonomy.md`）。マージしてよいかは CI と `scripts/merge-if-allowed.mjs` が機械的に判定しますが、テストが確かめていない誤りや、要件との食い違いは見つけられません。実装したエージェントが自分で見直すだけでは、同じ思い込みで見落としやすくなります。

## 決定

**Claude Code が作った変更は、PR を作る前に Codex にレビューを依頼する。** `scripts/codex-review.mjs` が、`origin/main` との差分のレビューを `codex exec` に読み取り専用のサンドボックスで依頼し、結果を `.data/reviews/` に残します。Claude Code は指摘を1件ずつ判断し、直すか、理由を添えて見送ります。指摘と対応は PR の本文に書きます。手順は `.claude/rules/workflow.md` の「Codex のレビュー」にあります。

**観点は、正しさ・セキュリティ・非機能の3つにする。** セキュリティは architecture.md の「セキュリティ」、ADR-0007、ADR-0009 を、非機能は requirements.md の NFR-xx を基準にします。CI とテストでは確かめにくい観点を、人のレビューの前に見るためです。`codex review --base` は指示文を受け付けず観点を指定できないため、`codex exec` に指示文（`scripts/codex-review.prompt.md`）と出力の JSON スキーマ（`scripts/codex-review.schema.json`）を渡します。差分をどう取り出すかは指示文に従う Codex に任せるので、スクリプトではベースとの差分を確かにレビューしたことまでは検証できません。

**レビューは1回、修正も1回で終える。** 指摘を元にまとめて1回直したら、再びレビューは依頼せずに PR を作ります。レビューと修正の往復が続いて作業が止まることを避けるためです。直したあとの確認は、`pnpm check`、CI、人のレビューに任せます。

**Codex を使えないときは止めない。** 未インストール、未ログイン、通信エラーなどでレビューできないときは、PR に「未実施」と理由を書いて進めます。レビューは品質を上げるための手順で、マージの条件にはしません。

**CI では実行しない。** CI で実物の LLM やエージェントを呼ばない方針（AGENTS.md）を守ります。

## 結果

- 差分（ソースコードと文書）が OpenAI に送られます。実データ（`~/.mymind/`）や `.env` はリポジトリに含めない方針なので、送られるのは開発中のコードと文書だけです
- Codex は `~/.codex` の認証情報を読み、自身のサンドボックスを使うため、Claude Code のサンドボックスの外で実行します（`.claude/settings.json` の `excludedCommands`）。`codex` を直接実行するときは、これまでどおり確認を求めます
- PR を作るまでの時間が、レビューの分（数分）だけ延びます
- Codex の出力はエージェントの出力として、スクリプトの中でもスキーマと同じ条件で確かめます。ルートのスクリプトは zod に依存していないため、条件を手で書いています
- レビューの結果は開発中のコードについての所見で、ADR-0009 の機微データ（アプリ利用者の振り返りなど）には当たらないため、`.data/reviews/` のパーミッションは既定のままにします
- Codex が実装した変更では、このレビューを省略します
