# ADR-0009：機微なデータは「クラウドに置いた場合」を基準に扱う

- ステータス：採用
- 日付：2026-09-22

## 背景

振り返りには、感情や思考、仕事上の人間関係が書かれます。今はローカルの SQLite に保存しますが、将来クラウドに置く可能性があります。後から保護の仕組みを足すと、データの持ち方やログの設計に手が入るため、「クラウドに置いた場合に必要になること」を基準に、今の段階で入れておくべきものを決めます。

## 決定

**データを分類する。** 次を「機微データ」とし、それ以外と区別して扱います。

| 分類 | 対象 |
|---|---|
| 機微データ | 振り返り（`thoughts_md`、`learning_md`）、タスクのメモ（`note_md`）、FB と総括の本文、調子の根拠、エージェントへの入力と出力、日ごとの記録のスナップショット |
| 通常データ | タスクのタイトル、ステータス、計画、イベント、設定 |

タスクのタイトルは通常データとしますが、画面の入力欄に「タイトルには個人名や機微な内容を書かない」旨は表示しません（利用者の自由に任せる）。

**機微データの読み書きは暗号化の差し込み口を通す。** `packages/db` のリポジトリ層で、機微データの列を読み書きするときは必ず `SensitiveCodec`（`encode` / `decode`）を通します。ローカルでは何もしない実装を使い、クラウドに移すときは、秘密情報として管理する鍵を使った列単位の暗号化に差し替えます。機微データは検索やソートの条件に使わない設計にしておきます（暗号化しても機能が壊れないようにするため）。

**ログに機微データを出さない。** アプリのログは構造化ログとし、機微データの項目は自動で伏せ字にします。エージェントの入出力ログだけは例外的に全文を残しますが、ローカルにだけ保存し、30日で自動削除します。クラウドではエージェントの入出力ログを保存しません。

**ファイルを守る。** DB、バックアップ、ログ、セッショントークンのファイルはパーミッション 600、ディレクトリは 700 で作ります。ディスク全体の暗号化は macOS の FileVault を前提とし、`pnpm doctor` で有効かどうかを確認します。

**バックアップを暗号化できるようにする。** バックアップの書き出しにも差し込み口を設け、ローカルでは任意、クラウドでは必須で暗号化します。ローカルで暗号化する場合の鍵は macOS のキーチェーンに保存します。

**削除できるようにする。** 利用者が特定の日の振り返りと FB を削除したら、DB から物理的に消します。バックアップからは保存期間の経過とともに消えることを、設定画面で説明します。

## 結果

クラウドに移すときは、`SensitiveCodec` とバックアップの暗号化の実装を差し替え、エージェントの入出力ログを無効にするだけで済みます。今の段階での負担は、リポジトリ層の差し込み口と、ログの伏せ字の仕組みです。
