# ADR-0012：画面のルーターは TanStack Router にし、フォントは @fontsource をそのまま同梱する

- ステータス：採用
- 日付：2026-09-23

## 背景

Web アプリの雛形（#37）を作る前に、次の2点が決まっていませんでした。

- architecture.md 2章の技術スタックにルーターがない。画面の URL は、issue 011（#20）の暫定決定で `/`、`/morning`、`/reflection/:day?`、`/backlog`、`/timeline`、`/calendar/:ym/:day?` と決まっている
- architecture.md 12.1 は「Noto Sans JP を常用漢字などに絞ったサブセットにする」としているが、サブセットを作るには元のフォントと道具が必要で、開発のサンドボックスから接続できるのは npm と GitHub だけ

## 決定

**ルーターは TanStack Router を使う。** TanStack Query と同じ系統で、URL のパラメーター（`:day`、`:ym`）を型付きで扱えます。ルートはコードで定義し（`createRoute`）、ファイル名からルートを作るためのプラグインは使いません。省略できるパラメーターは `{-$day}` の書き方で表します。

**フォントは @fontsource の WOFF2 をそのまま同梱する。** `@fontsource/inter` と `@fontsource/noto-sans-jp` を依存に加え、400・500・600・700 の4つの太さの CSS を読み込みます。Vite がビルド時に WOFF2 を同梱し、ブラウザは `unicode-range` で表示する文字を含むファイルだけを読み込みます。サブセットの自作はしません。外部のフォント配信サービスを使わない点（NFR-10）と、CSP の `font-src 'self'` は変わりません。

## 結果

- サブセットのスクリプトや、常用漢字の一覧を持たずに済みます。常用漢字にない字（人名など）も Noto Sans JP で表示され、ヒラギノとの混在が起きません
- 同梱するファイルは数が多くなります（文字の範囲ごとに分かれた WOFF2 を、太さごとに約100個）。`127.0.0.1` だけで使う今の構成では問題になりません。インターネットに公開する場合の見直しは #60 で扱います
- architecture.md 2章と 12.1、DESIGN.md 2.6 を、この決定に合わせて更新します
