# ADR-0002：FBはユーザーが明示的に依頼する

- ステータス：採用
- 日付：2026-09-22

## 背景

FBを生成するタイミングとして、振り返りの保存直後に自動で生成する案と、夜のうちに生成して翌朝に見せる案を検討しました。どちらも、生成のタイミング、取りこぼしの補完、完了の通知といった仕組みが必要になります。

## 決定

FBは自動では生成せず、ユーザーが「保存してFBをもらう」などのボタンで依頼したときだけ生成します。過去の日や月次総括も同じく、ボタンで依頼します。

## 結果

生成タイミングのスケジューラ、取りこぼしの補完、FB完了の通知が不要になります。FBをもらうこと自体が、振り返りを締めくくる区切りとして機能します。一方で、依頼を忘れた日にはFBがありません。そのため、カレンダーで「FBのない日」を識別できるようにし、後から依頼できるようにします。操作数を増やさないよう、振り返りの主ボタンを「保存してFBをもらう」にし、保存と依頼を1回の操作で済ませます。
