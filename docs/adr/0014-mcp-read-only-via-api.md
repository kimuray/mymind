# ADR-0014：MCP サーバーは公式 SDK で作り、読み取りだけを API 経由で出す

- ステータス：採用
- 日付：2026-10-05

## 背景

M5 の完了条件に「ターミナルの Claude Code から MCP 経由で記録を参照できること」があります。architecture.md は `packages/mcp`（stdio の MCP サーバー）を置くと書いていましたが、実装に使うライブラリ、出す範囲、データへのつなぎ方が決まっていませんでした（#165）。

FB の生成では、エージェントに決まった入力を渡して JSON を返してもらうだけで、ツールを使った自律的な操作はさせていません（ADR-0003）。MCP は、利用者がターミナルで対話しながら記録を見返すための別の入口です。

## 決定

**公式 SDK（`@modelcontextprotocol/sdk`）を使う。** stdio の JSON-RPC と MCP の規格を自前で書くと、規格の更新への追従を自分で持つことになります。SDK は Claude Code と Codex の両方で使われており、道具の定義と入力の検証（zod）をそのまま書けます。

**読み取りの道具だけを出す。** タスクの追加や状態の変更を MCP から許すと、画面の楽観的更新、業務日の確認（NFR-14）、古い画面からの更新の拒否（NFR-13）と同じ守りを MCP にも用意する必要があります。今回は見返すことが目的なので、書き換える道具は出しません（FR-M01）。

**出す道具は5つにする。** その日（`get_day`）、バックログ（`get_backlog`）、期間のタイムライン（`get_timeline`、2週間まで）、月（`get_month`）、タスク名の部分一致の検索（`search_tasks`）です（FR-M02）。返す値は API の応答そのもので、日数や件数はサーバーが計算した値を使います（FR-A10）。検索はタスク名だけを対象にし、振り返りや FB の本文の全文検索は対象外のままにします（requirements.md 6章）。

**DB を直接読まず、動いているサーバーの API を呼ぶ。** API を呼べば、機微データの扱い（暗号化の差し込み口、ADR-0009）、業務日の計算、集計を、画面と同じ1か所の実装で済ませられます。MCP サーバーはデータディレクトリのセッショントークンを読んで API を呼び、サーバーが動いていなければそのことを返します（FR-M03）。

## 結果

- 依存関係に `@modelcontextprotocol/sdk` を加えます（`packages/mcp` だけが使う）。依存関係の追加なので、実装の PR は人のレビューが必須です
- タスク名で探す API（`search_tasks` のため）がまだないので、実装の issue（#170）で読み取りの API を1つ足します
- MCP で渡した振り返りや FB は、呼んだエージェントの提供元に送られます。そのことを README の MCP の節と設定の画面に書きます（NFR-05）
- MCP サーバーはセッショントークンを読むため、データディレクトリと同じ利用者の権限で動かします。トークンを MCP の外へ出しません
- 書き換える道具が必要になったら、NFR-13・NFR-14 の守りを API と同じに用意したうえで、新しい ADR で判断します
