# ADR-0017：デスクトップアプリの更新は、手元のリポジトリを更新元にする

- ステータス：採用
- 日付：2026-10-09

## 背景

デスクトップアプリ（ADR-0015）は、自分用の署名なしの `.app` を手元で作って入れています（ADR-0016、NFR-25）。新しいバージョンにするには、`pnpm update-app` のあとに、アプリを終了し、`pnpm desktop:package` で作り直し、`/Applications` のものと入れ替えて開き直す必要があり、手間がかかっていました。利用者からは、アプリの上で「アップデートがあります」と知らせ、そこから更新できるようにしたいという要望が出ました。

更新元の候補は2つありました。

| 候補 | 良いところ | 困るところ |
|---|---|---|
| 手元のリポジトリ（git fetch で origin/main と比べ、そのリポジトリでビルドする） | CI、署名、トークンが要らない。今の作り方（手元でビルド）を変えない | 手元にリポジトリと pnpm が要る。ビルドに数分かかる |
| GitHub Releases（CI で `.app` を作り、アプリが落として入れ替える） | ビルドが要らず速い | 非公開のリポジトリではトークンをキーチェーンに置く必要がある。署名していないので Electron 標準の `autoUpdater`（Squirrel.Mac）が使えず、入れ替えを自前で作る必要がある |

## 決定

**更新元は、`.app` を作った手元のリポジトリにする。** `.app` を作るとき、`scripts/packageApp.mjs` が、作ったコミット（完全なハッシュ）とリポジトリの場所を `Resources/app/build-info.json` に書きます。アプリはこれを読み、`git fetch origin main` のあと、origin/main がそのコミットより先に進んでいれば、メニューバーのメニューと OS の通知で知らせます（FR-U05）。変更の件数は `git rev-list --count` で数えます（AI にもアプリのコードにも数えさせない）。

**確かめるのは、起動して1分後と、6時間おき。** メニューの「アップデートを確認」からも確かめられます。取得できないとき（オフラインなど）は、定期の確認では何も知らせません。更新の確認は、エージェント以外で外部と通信する唯一の機能です（NFR-11 の例外として requirements.md に書く）。通信先は、リポジトリの `origin`（GitHub）だけです。git にはパスワードやパスフレーズを尋ねさせず（`GIT_TERMINAL_PROMPT=0`、`ssh -o BatchMode=yes`）、入力を待って止まらないようにします。

**適用は `pnpm update-app` に任せる。** `pnpm update-app` を広げ、`/Applications/mymind.app` が入っていれば、`.app` の作成、動いているアプリの終了（Apple Event の quit。メニューの「mymind を終了」と同じくサーバーを止めてから終わる）、入れ替え（古い `.app` を脇に退け、写せなければ戻す）、開き直しまでを行います。アプリの「再起動して更新」は、確かめのダイアログのあと、このスクリプトを別のプロセスグループで動かすだけです。ターミナルからの更新とアプリからの更新が同じ手順になります。出力は `~/Library/Logs/mymind/update-<時刻>.log` に書き、失敗したらメニューからログを開けます。

**`apps/desktop` で `child_process` を使うのは、更新のコマンドを動かす1ファイルだけにする。** 依存方向の規則（`no-child-process-outside-agent`）は、エージェントの起動を `packages/agent` に閉じ込めるためのものです。git と pnpm はエージェントではなく、`apps/desktop` は `packages/agent` を読み込めない（ADR-0015）ので、`apps/desktop/src/updateCommands.ts` だけを例外にします。PATH は ADR-0016 と同じ理由で、今の PATH によく使われる場所（`/opt/homebrew/bin`、`~/Library/pnpm` など）を足して作ります。

## 結果

- 初めて入れるときは、これまでどおり手で `/Applications` に置きます（署名していない `.app` を開く操作を、手順で読んでもらうため）。`pnpm update-app` は、入っていない `.app` を自動では入れません
- 入っている `.app` が今のコミットから作られていれば、`pnpm update-app` は作り直しません（`--force` で作り直す）。デスクトップアプリを使わない場合は `--no-app` で省けます
- `pnpm update-app` は main にいて、コミットしていない変更がないことを求めます。`.app` を作ったリポジトリが別のブランチにいると、アプリからの更新は失敗し、ログにその理由が出ます
- GitHub Releases からの更新は、署名や公開の配布を考えるときに、新しい ADR で改めて判断します
