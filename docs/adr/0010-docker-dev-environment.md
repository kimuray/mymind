# ADR-0010：Docker と Docker Compose で開発環境を用意する

- ステータス：採用
- 日付：2026-09-22

## 背景

開発環境をホストの macOS だけに頼ると、Node やブラウザのバージョンの違いで、エージェントと人、CI の間で結果がずれることがあります。また、エージェントに自律的に作業させる場合、ホストから隔離された環境で動かせる選択肢があると安心です。一方で、mymind の本番の常駐（launchd）、デスクトップ通知、キーチェーン、実物の Claude Code / Codex の起動は macOS のホストでしか行えません。

## 決定

**Docker は開発とテスト専用にする。** Docker Compose で次の3つのサービスを用意します。本番の常駐はこれまでどおりホストで行います。

| サービス | 用途 |
|---|---|
| `dev` | 開発サーバー（Vite と Hono）。ホストのブラウザから `http://127.0.0.1:5173` で開く |
| `check` | `pnpm check`（lint、型、依存方向、デザイントークン、設計文書、テスト） |
| `e2e` | 本番ビルドに対する E2E。lockfile と同じバージョンの Chromium を入れたイメージで実行する |

VS Code などから同じ環境に入れるよう、`dev` サービスを使う devcontainer の設定も置きます。

**ソースはバインドマウント、依存関係はボリューム。** ソースコードはホストと共有し、`node_modules` と pnpm のストアは名前付きボリュームに置きます。ネイティブモジュールがあってもホストとコンテナで混ざらず、ワークスペース内の各パッケージの `node_modules` は相対リンクなので、どちらの環境からも正しく解決されます。

**コンテナ内でもローカルサーバーの保護を崩さない（ADR-0007 の補足）。** コンテナの中ではホストからの接続を受けるために `0.0.0.0` で待ち受ける必要があります。これは環境変数 `MYMIND_HOST=0.0.0.0` で指定し、サーバーは `MYMIND_IN_CONTAINER=1` が設定されているとき（Docker イメージが設定する）だけこれを受け入れます。ポートはホストの `127.0.0.1` にだけ公開し、外部のマシンからは到達できないようにします。Host・Origin・トークンの検証は変わりません。

**実データとエージェントに触れない。** コンテナ内のデータディレクトリは `./.data/docker`（E2E は `./.data/e2e`）に固定し、`~/.mymind` はマウントしません。エージェントは常に偽のアダプタ（`MYMIND_AGENT=fake`）を使います。

**Docker の操作は人の承認を必要にする。** Docker の操作はホストの管理者権限に近い力を持つため、Claude Code の権限設定で `docker` コマンドは確認を求める扱いにし、サンドボックスからも除外しません。Dockerfile、compose.yaml、devcontainer の変更はレビュー必須にします。

## 結果

人、エージェント、CI が同じ手順（`docker compose run --rm check`）で同じ結果を得られます。Docker 関連のファイルが壊れていないことは、CI の `docker.yml` で確認します。一方で、実物のエージェントを使う確認、launchd、通知は、これまでどおりホストで行う必要があります。
