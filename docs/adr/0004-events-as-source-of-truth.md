# ADR-0004：状態の履歴はイベントを正本にする

- ステータス：採用
- 日付：2026-09-22

## 背景

「いつ着手して、いつ終わったか」「着手中・中断・待ちがそれぞれ何日だったか」を後から正確に見られることが、このツールの重要な要件です。タスクに `started_at` や `completed_at` を持たせるだけでは、中断と再開を繰り返したタスクや、複数日にまたがる状態の変化を表現できません。

## 決定

ステータスが変わるたびに、変更前後のステータス、時刻、業務日を `task_events` に記録し、これを履歴の正本とします。`tasks.status` は現在の状態を速く読むための写しとし、イベントと同じトランザクションで更新します。今日の計画も `day_plans` に日ごとに残し、持ち越しの履歴を追えるようにします。

## 結果

タイムラインの区間、状態ごとの日数、持ち越し回数を、すべてイベントから計算できます。AIに渡す集計値もここから作れます。一方で、`tasks.status` とイベントが食い違わないよう、状態を変える処理はすべてドメイン層の関数を経由させ、直接の更新を禁止します。
