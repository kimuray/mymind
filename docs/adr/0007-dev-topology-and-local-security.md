# ADR-0007：開発時と本番時のサーバー構成と、ローカルサーバーの保護

- ステータス：採用
- 日付：2026-09-22

## 背景

本番（常駐時）は Hono の1プロセスがAPIと画面を配信しますが、開発中は Vite の開発サーバーが別に動きます。このままだと、Origin の検証、セッショントークンの受け渡し、CSP が開発時だけ壊れ、エージェントが「動かすために検証を緩める」方向に流れやすくなります。

## 決定

**ブラウザから見える入口を常に1つにする。** 開発中はブラウザが Vite の開発サーバーだけにアクセスし、`/api` は Vite のプロキシで Hono に転送します。本番では Hono が静的ファイルとAPIを同じポートで配信します。どちらの場合も、画面とAPIは同一オリジンになります。

**リクエストの検証は多層にする。** すべてのリクエストで `Host` が許可リスト（`127.0.0.1:<port>` と `localhost:<port>`、開発時は Vite のポートも）に含まれることを確認します（DNSリバインディング対策）。状態を変更するリクエストでは、さらに次の3つをすべて確認します。

1. `Sec-Fetch-Site` ヘッダーが `same-origin` であること（Fetch Metadata による判定）
2. `Origin` ヘッダーが許可リストに含まれること
3. `X-Mymind-Token` ヘッダーのセッショントークンが一致すること（独自ヘッダーのため、外部サイトからはCORSのプリフライトなしに送れない）

**セッショントークンは起動ごとに生成し、HTMLの meta タグで渡す。** サーバーは起動時にランダムなトークンを生成し、データディレクトリにパーミッション 600 で書き出します。本番では Hono が `index.html` を返すときに meta タグとして埋め込み、開発時は Vite のプラグイン（`transformIndexHtml`）が同じファイルを読んで埋め込みます。トークンをAPIで返すエンドポイントは作りません。

**CSP は本番ビルドで厳格にし、E2E は本番ビルドに対して実行する。** 本番では `default-src 'self'`、`script-src 'self'`、`style-src 'self' 'nonce-…'`、`connect-src 'self'`、`frame-ancestors 'none'` を基本にします。CodeMirror には `EditorView.cspNonce` でノンスを渡します。開発サーバーでは Vite の HMR のため CSP を付けません。その代わり、E2E テストは必ず本番ビルドをHonoで配信した状態で実行し、CSP違反を検出します。

**待ち受けは 127.0.0.1 のみ。** ポートが使用中なら別のポートを探さずに起動を失敗させ、原因を表示します（Origin の許可リストがずれるのを防ぐため）。

## 結果

開発時と本番時で、検証の仕組みを同じまま保てます。エージェントが検証を無効化して回避する必要がなくなります。一方、E2E の前に本番ビルドが必要になるため、E2E の実行時間は長くなります。
