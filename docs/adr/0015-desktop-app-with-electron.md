# ADR-0015：画面の入口をデスクトップアプリにし、Electron で apps/desktop に作る

- ステータス：採用（spike の結果と、事前に確かめる範囲の変更は ADR-0016）
- 日付：2026-10-05

## 背景

mymind は、PC 上の Node.js サーバーを `127.0.0.1` で動かし、ブラウザから使ってきました（ADR-0001）。M5 までで、日々の TODO、振り返りと FB、記録の見返し、バックアップ、通知、MCP がそろいました。一方、ブラウザで使い続けるには次の手間が残っています。

- 常駐を launchd で用意する必要があり、GUI から起動したときと同じ環境（PATH、エージェントのログイン状態）でサーバーを動かすのが難しい（#12）
- 通知は、`terminal-notifier` を別に入れるか、タブを開いたままブラウザの通知を許可するかで、出し方が3通りに分かれた（#169）
- タブを閉じると、アプリを開いていることが分からなくなる。普段使いの道具として、Dock やメニューバーから開ける形がほしい

利用者は、これまでの全機能をデスクトップアプリに載せて、ブラウザで使う形から置き換えることを決めました（2026-10-05）。

## 決定

**Electron で作り、このリポジトリの `apps/desktop` に置く。** サーバーは Node.js の API（`node:sqlite`、`child_process`、`fs`）を前提にしています。Electron は Node.js を同梱しているので、`apps/server` をほぼ変えずに動かせます。Tauri は軽量ですが、バックエンドが Rust なので、Node.js のサーバーを別のプロセスとして同梱する必要があり、構成が複雑になります。

別のリポジトリにはしません。`packages/domain`・`db`・`agent`、`apps/server`、`apps/web` の画面をそのまま使い、issue、CI、ルール（AGENTS.md、`.claude/rules/`）も引き継ぐためです。

**サーバーは Electron の子プロセス（`utilityProcess`）で動かし、メインプロセスが見守る。** メインプロセスは、起動するとサーバーを子プロセスで起動します。サーバーが異常終了したら起動し直し、短い間に繰り返し落ちたら諦めて、理由を画面とログに出します。画面の描画とサーバーを別のプロセスにするのは、片方が落ちてももう片方を残すためです。これで「異常終了しても再起動する」（M5 の完了条件）を、launchd を使わずに満たします。

**ウィンドウは、今と同じ `http://127.0.0.1:<port>` の画面を開く。** 画面と API の通信は HTTP と SSE のまま変えません。ADR-0007 の守り（Host・Origin・Fetch Metadata の検証、セッショントークン、CSP）をそのまま使えます。MCP（ADR-0014）も、同じ API を呼ぶので変えずに使えます。ウィンドウは `contextIsolation`、`sandbox` を有効にし、`nodeIntegration` を無効にします。画面に Node.js の API は渡しません。画面からメインプロセスへの依頼が必要なとき（通知のクリックで画面を移る、など）は、preload で用途を絞った関数だけを出します。ウィンドウから外部の URL へは移らせず、外部のリンクは既定のブラウザで開きます。

**常駐はログイン時の起動とメニューバーで行う。** `app.setLoginItemSettings` でログイン時に起動します。ウィンドウを閉じてもアプリは終了せず、メニューバーのアイコンから開き直せます。ウィンドウを閉じている間も、サーバーは通知と毎日のバックアップのために動き続けます。閉じたウィンドウは隠さずに破棄し、待機中のメモリを抑えます（NFR-19 はサーバーのプロセスについての基準のまま）。アプリの二重起動は `app.requestSingleInstanceLock` で防ぎ、2つ目を起動したら1つ目のウィンドウを前に出します。サーバーのロックファイル（NFR-20）はそのまま使います。

**通知は OS の通知に一本化する。** サーバーは、通知を出すときに子プロセスの通信路（`parentPort`）でメインプロセスに頼みます。メインプロセスは Electron の `Notification` で出し、クリックされたらウィンドウを開いて（閉じていれば作り直して）その種類の画面へ移ります。デスクトップアプリで動いていないとき（開発中にブラウザで開いたとき、E2E）は、これまでの手段（`terminal-notifier`、ブラウザの通知、画面のバナー、architecture.md 9.2）を使います。

**データの場所は変えない。** DB、バックアップ、ログ、セッショントークンは今までどおり `~/.mymind/`（`MYMIND_DATA_DIR` で変えられる）に置きます。ブラウザ版から移るときに、データを移す作業はありません。

**配布は、当面は自分で使うための署名なしのビルドにする（暫定）。** `pnpm` のスクリプトで `.app` を作り、自分の Mac に置いて使います。Apple の署名と公証、自動更新は、他の人に配るときに改めて決めます。更新はこれまでどおりリポジトリを更新してビルドし直します。

**ブラウザで開く入口は、開発と E2E のために残す。** 正式な使い方はデスクトップアプリにします。ただし、画面の開発（Vite）と E2E（Playwright でブラウザを使う）は今の仕組みのまま続け、Electron に固有の動き（起動、常駐、通知、ウィンドウ）は、Playwright の Electron 対応で別に確かめます。

## 確かめてから進めること（spike）

次の3点は、実装の前に spike で確かめます。どれかが成り立たなければ、この ADR の該当する部分を新しい ADR で見直します。

1. Electron に同梱された Node.js で `node:sqlite` が使えること（ADR-0011）。使えない Electron の版なら、使える版を選ぶ
2. GUI から起動したアプリの子プロセスから、`claude` と `codex` の CLI が見つかり、ログインした状態で動くこと（ADR-0005）。PATH が短いときの補い方を決める
3. ビルドした `.app` で、`apps/server` と `apps/web` のビルドの成果物、マイグレーション、プロンプトを読めること

## 結果

- 依存関係に `electron` と、`.app` を作る道具（spike で選ぶ）を、`apps/desktop` の開発用の依存として加えます。依存関係の追加なので、実装の PR は人のレビューが必須です
- `apps/desktop` は `apps/server` を起動するために読み込みます。依存の向きは `domain` ← `db` / `agent` ← `server` ← `desktop` とし、`apps/web` は `apps/desktop` を読み込みません。dependency-cruiser の規則に加えます
- 常駐の launchd（#12）は作りません。M5 の完了条件のうち「ログイン時の起動と、異常終了時の再起動」は、M6 のデスクトップアプリで満たします
- 通知の `terminal-notifier`、ブラウザの通知、画面のバナー（#169）は、デスクトップアプリで動いていないときの代わりとして残します。デスクトップアプリでは OS の通知だけを使います
- requirements.md の NFR-01（動作環境）、NFR-17（対応ブラウザ）、NFR-27（対応OS）を、デスクトップアプリに合わせて書き直します
- ADR-0001 の「ブラウザから使う」は、この ADR で「デスクトップアプリのウィンドウから使う」に変わります。サーバーを `127.0.0.1` で動かし、エージェントを子プロセスで直接起動するという中心の判断は変わりません
- CI（Linux）では、Electron の起動の確かめを仮想ディスプレイの上で行います。macOS に固有の動き（ログイン時の起動、メニューバー、OS の通知の見た目）は、実機で人が確かめます
