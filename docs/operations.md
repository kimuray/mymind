# 運用の手順

手元で mymind を使い続けるための手順です。デスクトップアプリのインストールと更新、ブラウザ版からの移り方、バックアップからの復元をまとめます（NFR-04、NFR-25、ADR-0015）。

## データの場所

実データは `~/.mymind/`（`MYMIND_DATA_DIR` で変更できる）にあります。

| パス | 内容 |
|---|---|
| `mymind.db`（と `-wal`、`-shm`） | DB。本人だけが読める（600） |
| `backups/pre-migration-<時刻>.db` | マイグレーションの前に自動で取ったスナップショット |
| `backups/before-restore-<時刻>.db` | 復元の直前に残した、入れ替える前の DB |
| `backups/daily-<時刻>.db` | 毎日 3:30（日本時間）に取るスナップショット。保存先は設定の「バックアップ」で変えられ、初期値は14世代 |
| `daily-backup.json` | 最後の毎日のバックアップの結果（成功・失敗と理由）。設定の「最後のバックアップ」に出す |
| `logs/server/<日付>.log` | サーバーのログ（JSON の1行ずつ。機微データは伏せ字）。日付は日本時間で、14日を過ぎたら消える |
| `logs/agent/<業務日>/` | エージェントの入出力の全文（機微データ）。30日を過ぎたら消える |
| `window-state.json`、`desktop-state.json` | （デスクトップアプリ）ウィンドウの大きさと位置、ログイン時の起動を初回に設定したか。`~/Library/Application Support/mymind/` に置く |
| `mymind.lock` | 起動中のサーバーの PID。同じデータディレクトリで2つ起動しないためのロック |

時刻は UTC で、`20260925T075324Z` の形です。

毎日のバックアップは、書き出したあとに開いて整合性を確かめ（`PRAGMA integrity_check`）、通ったものだけを残します。通らない、または保存先に書けないときは、ファイルを残さずに失敗として記録し、設定の「最後のバックアップ」に「失敗」と出します。翌日にまた試します。PC が眠っていて 3:30 を過ぎた場合は復帰したときに、サーバーが止まっていた場合は起動したとき（最後の毎日のバックアップが24時間より古ければ）に取ります。毎日のバックアップから戻す手順も、下の「バックアップから戻す」と同じです。

## デスクトップアプリを入れる

自分用の `mymind.app`（署名なし）を作って、アプリケーションのフォルダに置きます（ADR-0015、ADR-0016）。

```sh
pnpm desktop:package
```

`pnpm build` のあと、`apps/desktop/out/mymind-darwin-<arm64 または x64>/mymind.app` ができます。これを `/Applications` に移してください。

- 署名していないので、初めて開くときは macOS に止められます。Finder で `mymind.app` を Control キーを押しながらクリックし、「開く」を選んでください。それでも開けないときは、ターミナルで `xattr -dr com.apple.quarantine /Applications/mymind.app` を実行します
- 初めて開くと、ログイン時に起動するよう設定します（設定の「デスクトップアプリ」で変えられます）。ウィンドウを閉じてもメニューバーに残り、通知と毎日のバックアップを続けます。終わらせるときは、メニューバーのマメの「mymind を終了」か ⌘Q です
- 初めて通知を出すとき、macOS が通知の許可を尋ねます。届かないときは「システム設定」の「通知」で mymind を許可してください
- データは今までどおり `~/.mymind/` を使います。ポートは 4820 で、MCP（`packages/mcp`）もアプリが動いている間に使えます
- `claude` と `codex` は、ログインシェルの PATH と、よく使われる場所（`~/.local/bin`、`~/.asdf/shims`、`/opt/homebrew/bin` など）から探します（ADR-0016）。設定の状態で「見つかりません」と出るときは、そのどこかに置くか、ログインシェル（`$SHELL`）の設定で PATH に足してください

### ブラウザ版から移る

データの場所は変わらないので、移すデータはありません。

1. ブラウザ版のサーバー（`pnpm start` など）を止める。launchd などで常駐させていた場合は、その設定も外す（`launchctl bootout gui/$(id -u)/<ラベル>` と、`~/Library/LaunchAgents/` の plist の削除）。同じデータディレクトリで2つは起動できないため（NFR-20）
2. 上の手順で `mymind.app` を入れて開く
3. 開いていたブラウザのタブは閉じる。ブラウザの通知や `terminal-notifier` は使わなくなる（デスクトップアプリは OS の通知を使う）

## 新しいバージョンにする

```sh
pnpm update-app
```

`main` にいてコミットしていない変更がないことを確かめてから、`git pull --ff-only`、`pnpm install --frozen-lockfile`、`pnpm build` を順に実行します。

デスクトップアプリを使っている場合は、続けて次を行います。

1. メニューバーのマメから「mymind を終了」する（サーバーも止まる）
2. `pnpm desktop:package` で `mymind.app` を作り直し、`/Applications` のものと入れ替える
3. 開く。まだ適用していないマイグレーションがあれば、適用の前に自動でスナップショットを取る（下の「バックアップから戻す」）

再起動のとき、まだ適用していないマイグレーションがあれば、サーバーは**適用の前に** `backups/pre-migration-<時刻>.db` へスナップショットを取り、次のように表示します。

```
マイグレーション（20260924132619_agent_jobs）の前にバックアップしました: ~/.mymind/backups/pre-migration-20260925T075324Z.db
```

新しく作る DB と、すべて適用済みの DB では取りません。

## バックアップから戻す

マイグレーションに失敗したときや、データを誤って壊したときに使います。

1. サーバーを止める（動いているあいだは、戻すコマンドが拒否します）
2. 戻したいファイルを選ぶ

   ```sh
   ls -l ~/.mymind/backups/
   ```

3. 戻す

   ```sh
   pnpm restore-backup ~/.mymind/backups/pre-migration-20260925T075324Z.db
   ```

   コマンドは次の順に処理します。

   - バックアップが壊れていないこと（`PRAGMA integrity_check`）と、mymind の DB であること（マイグレーションの記録があること）を確かめる。だめなら今の DB に触れずに終わる
   - サーバーと同じロックを取る。サーバーが動いていれば終わる
   - 今の DB を `backups/before-restore-<時刻>.db` に残す
   - 古い `-wal` と `-shm` を消し、バックアップを `mymind.db` に写す（600）

4. 古いバージョンのコードで使う場合は、`git checkout` でマイグレーションを失敗する前のコミットに戻す。新しいバージョンのまま起動すると、足りないマイグレーションがもう一度適用される（その前に改めてスナップショットを取る）
5. サーバーを起動し、画面でデータを確かめる

戻したあとで「やはり戻す前がよかった」ときは、同じ手順で `before-restore-<時刻>.db` を指定します。

## 復元を試す

復元できることは、`apps/server/src/backups.test.ts` で、実際の SQLite のファイルを使って確かめています（入れ替え、戻す前の DB の保存、サーバーが動いているときの拒否、壊れたファイルの拒否）。

手元の環境で試すときは、実データに触れないように、別のデータディレクトリを使います。

```sh
# start はパッケージのディレクトリで動くので、データディレクトリは絶対パスで渡す
export MYMIND_DATA_DIR="$PWD/.data/restore-trial" MYMIND_PORT=4831
pnpm --filter @mymind/server start   # 画面でタスクを1つ追加して止める
pnpm restore-backup <戻したいファイル>
pnpm --filter @mymind/server start   # 戻っていることを確かめる
```
