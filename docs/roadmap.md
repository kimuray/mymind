# ロードマップ

各マイルストーンを構成する作業は GitHub の issue に分割しています。各マイルストーンは「使える状態」で区切っています。完了条件をすべて満たしたら次へ進みます。括弧内は requirements.md の要件IDです。

## M1：毎日のTODO管理ができる

リポジトリの雛形、開発ハーネス、ドメイン層、今日とバックログの画面を作ります。

完了条件は次のとおりです。今日とバックログにタスクを追加し、親子で整理できること（FR-T01, T02）。6つのステータスを遷移表どおりに切り替えられ、変更がイベントとして記録されること（FR-T03, T04）。今日・明日・バックログの間で移動でき、自動ルールが働くこと（FR-T05〜T08）。「◯日目」のバッジが表示されること（FR-T12）。リストのキー操作が使えること（FR-U01の5.2節）。業務日の計算、遷移表、自動ルールの単体テストがそろい、CIで lint・typecheck・テストが通ること。

## M5：毎日放っておいても回る

常駐、バックアップ、通知、MCPサーバーを整えます。

完了条件は次のとおりです。ログイン時にサーバーが起動し、異常終了しても再起動すること。DBのスナップショットが毎日保存されること（NFR-04）。朝・夜・棚卸しの通知が条件どおりに届き、クリックで該当画面が開くこと（FR-N01〜N05）。ターミナルのClaude CodeからMCP経由で記録を参照できること。

ログイン時の起動と異常終了時の再起動は、launchd（#12）ではなく、M6 のデスクトップアプリで満たします（ADR-0015）。バックアップ、通知の条件と出し方、MCP は M5 で実装済みです。

## M6：デスクトップアプリで使える

画面の入口をブラウザからデスクトップアプリ（Electron、`apps/desktop`）に置き換え、M1〜M5 のすべての機能をデスクトップアプリで使えるようにします（ADR-0015）。サーバー、DB、画面のコードは今のものをそのまま使い、データの場所（`~/.mymind/`）も変えません。

進め方は次の順です。

1. **spike**：Electron の中で `node:sqlite` が使えること、GUI から起動したアプリから `claude` と `codex` が動くこと、ビルドした `.app` からサーバーと画面の成果物を読めることを確かめ、Electron の版と `.app` を作る道具を決める
2. **アプリの殻**：起動するとサーバーを子プロセスで動かし、ウィンドウで全画面を開く。サーバーの異常終了を見守って起動し直す。二重起動を防ぐ。開発時の起動（`pnpm desktop:dev`）を用意する
3. **常駐**：ログイン時の起動、ウィンドウを閉じてもメニューバーに残ること、メニューバーからの操作（開く、今日の画面、終了）
4. **通知**：サーバーからメインプロセスに頼んで OS の通知を出し、クリックでウィンドウを開いて該当画面へ移る。デスクトップアプリで動いていないときは、これまでの手段を使う
5. **アプリとしての手触り**：アプリのメニューとショートカット（`⌘K`、`⌘P` などの既存のキーと重ならないこと）、ウィンドウの大きさと位置を覚えること、外部のリンクを既定のブラウザで開くこと、アプリのアイコン
6. **配布と移行**：自分用の `.app` を作るスクリプト（署名なし）、更新の手順、ブラウザ版からの移り方（launchd を使っていた場合の止め方を含む）を `docs/operations.md` に書く

完了条件は次のとおりです。

- デスクトップアプリから、M1〜M5 のすべての画面と操作が使えること（今日、朝の計画、振り返りと FB、バックログ、タイムライン、カレンダー、月次総括、棚卸し、設定、コマンドパレット）。E2E は今までどおり画面に対して通り、Electron の起動と画面の表示を確かめるテストが CI で通ること
- ログイン時にアプリが起動し、ウィンドウを閉じてもメニューバーに残り、サーバーが異常終了しても起動し直すこと（M5 の常駐の条件）
- ウィンドウを閉じていても、毎日のバックアップが取られ、朝・夜・棚卸しの通知が OS の通知で届き、クリックで該当画面が開くこと（NFR-04、FR-N01〜N05）
- アプリが動いている間、ターミナルの Claude Code から MCP で記録を参照できること（FR-M01〜M03）
- Claude Code と Codex で、FB と月次総括を依頼できること（FR-A01、FR-A06）
- 自分用の `.app` をスクリプトで作れ、更新と移行の手順が `docs/operations.md` にあること
- 実機（macOS）での確認：ログイン時の起動、メニューバー、OS の通知とクリック、エージェントの起動（人の作業）

## M7：タスクを整理できる

タスクのメモと、任意のタグを使えるようにします。タグは、表示・絞り込みに加えて、記録の見返しと FB にも使います。

完了条件は次のとおりです。

- タスクの詳細で、メモを Markdown で書いてプレビューでき、書きかけが失われないこと（FR-T09、NFR-12）
- タスクにタグを付け外しでき、付けるときにその場で作れること。タグが行と詳細に表示されること。設定の画面で名前と色を変え、削除できること（FR-T13）
- 今日・バックログの一覧をタグで絞り込めること。コマンドパレットからも絞り込めること（FR-T14）
- タイムライン・カレンダー・月次総括で、タグごとの件数と日数を見られること（FR-R08）
- FB と月次総括の入力にタグの名前が入り、送信内容の確認（FR-A12）にも出ること（FR-A13）


## M8：ニューモフィズムの見た目になる

画面の質感を、すりガラスからニューモフィズム（面を地と同じ色で塗り、明るい影と暗い影で浮き出させたり、へこませたりする表現）に変えます（ADR-0018）。機能、画面の構成、キー操作、マメは変えません。

進め方は次の順です。

1. **トークンと地**：凸凹のトークン（`--surface`、`--neu-*`）を足し、ガラスと背景のにじみを外す。DESIGN.md、requirements.md（NFR-22）、コントラストのテストを同じ PR で直す
2. **Figma**：変数、エフェクトスタイル、部品、8枚のフレームを作り直す
3. **共通部品**：ボタン、入力欄、セグメント、`kbd`、チップ、ステータスアイコン
4. **3ペインとリスト**：サイドバー、メイン、詳細ペイン、リストの行と選択
5. **画面ごと**：朝の計画、振り返り、バックログと棚卸し、タイムライン、カレンダー、月次総括、設定
6. **重なる面**：ダイアログ、コマンドパレット、通知のバナー、デスクトップアプリのアイコン
7. **確認**：ふだんの画面での axe の検査、スクリーンショットと Figma の突き合わせ

完了条件は次のとおりです。

- すべての画面とダイアログで、面が地と同じ色の凸凹で表され、`--glass-*`、`--blob-*`、`backdrop-filter` がコードに残っていないこと
- 本文のコントラストが 4.5:1 以上で、ふだんの画面に対する axe の検査が E2E で通ること（NFR-06）
- 押せる要素がホバーと押下で反応し、選んだ行とフォーカスが影だけに頼らず見分けられること（NFR-29、NFR-06）。「コントラストを上げる」設定で縁が濃くなること
- Figma の8枚のフレームと Components が新しい質感になり、`pnpm screenshots` の画像と並べて違いが説明できること
- DESIGN.md と `tokens.css` の値が一致していること
