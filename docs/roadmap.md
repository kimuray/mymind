# ロードマップ

各マイルストーンを構成する作業は GitHub の issue に分割しています。各マイルストーンは「使える状態」で区切っています。完了条件をすべて満たしたら次へ進みます。括弧内は requirements.md の要件IDです。

## M1：毎日のTODO管理ができる

リポジトリの雛形、開発ハーネス、ドメイン層、今日とバックログの画面を作ります。

完了条件は次のとおりです。今日とバックログにタスクを追加し、親子で整理できること（FR-T01, T02）。6つのステータスを遷移表どおりに切り替えられ、変更がイベントとして記録されること（FR-T03, T04）。今日・明日・バックログの間で移動でき、自動ルールが働くこと（FR-T05〜T08）。「◯日目」のバッジが表示されること（FR-T12）。リストのキー操作が使えること（FR-U01の5.2節）。業務日の計算、遷移表、自動ルールの単体テストがそろい、CIで lint・typecheck・テストが通ること。

## M2：1日の流れが回る

朝の計画と夜の振り返りを作ります。

完了条件は次のとおりです。朝の計画で持ち越しを判断し、バックログから選び、まとめて確定できること（FR-D03〜D05）。振り返りをMarkdownで書いてプレビューでき、自動の記録サマリーが表示されること（FR-D06, D07）。保存のみで保存できること（FR-D08の一部）。localhostのセキュリティ対策（Host・Originの検証、セッショントークン、CSP、Markdownのサニタイズ）が入っていること（NFR-02）。朝の計画から振り返りまでの流れがE2Eテストで確認できること。

完了：2026-10-03（朝の計画の画面と、朝から振り返りまでの E2E、#111。`⌘P` の実機での確認は #35 で続け、2026-10-04 に確認した）

## M3：振り返りのあとにFBが届く

ジョブランナーとエージェント連携を作ります。

完了条件は次のとおりです。「保存してFBをもらう」でClaude CodeまたはCodexが起動し、FBと調子が表示されること（FR-A01, A02, A07）。生成中の表示、キャンセル、失敗時の再試行ができること（FR-A08）。調子を手動で修正でき、両方の値が残ること（FR-A03）。再依頼でFBの履歴が残ること（FR-A04）。朝の計画画面に前日のFBが表示されること（FR-D02）。マメのコンポーネントが7つの表情で表示できること。偽のアダプタを使ったE2Eテストと、出力例を使った検証処理のテストがあること。

完了：2026-10-04（日次 FB のプロンプト 1.0.0、#127。エージェントの選択、#129。Claude Code と Codex の実機での起動は #10 で確認済み）

## M4：記録を見返せる

タイムライン、カレンダー、月次総括、棚卸しを作ります。

完了条件は次のとおりです。タイムラインで状態ごとの期間、調子のレーン、内訳が表示されること（FR-R01〜R03）。カレンダーで日ごとの記録を見られ、FBのない日に後からFBを依頼できること（FR-R04, FR-A05, A09）。月次総括を途中経過も含めて依頼・表示できること（FR-A06, FR-R05）。棚卸しで対象を判断できること（FR-R06）。コマンドパレットとショートカット一覧が使えること（FR-U02, U03）。

完了：2026-10-04（タイムライン #145・#148・#155、カレンダー #146・#149、月次総括 #147・#154、棚卸し #143・#150、コマンドパレット #151。月次総括のプロンプトは 0.1.0（下書き）で、実物のエージェントでの評価と 1.0.0 は #140 で続ける）

## M5：毎日放っておいても回る

常駐、バックアップ、通知、MCPサーバーを整えます。

完了条件は次のとおりです。ログイン時にサーバーが起動し、異常終了しても再起動すること。DBのスナップショットが毎日保存されること（NFR-04）。朝・夜・棚卸しの通知が条件どおりに届き、クリックで該当画面が開くこと（FR-N01〜N05）。ターミナルのClaude CodeからMCP経由で記録を参照できること。
