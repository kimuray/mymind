# 作業記録

エージェントが、issue を1つ終えるたびに1件の記録を書きます。セッションが途切れたときや、別のエージェントが引き継ぐときの起点になります。

直近の記録は `pnpm progress`（件数を変えるときは `pnpm progress 20`）で、新しい順の表として読めます。人が読むための HTML（`pnpm docs:build`）では、このページの末尾にすべての記録を表にして載せます。

## 書き方

1件を1ファイルにして、このディレクトリに置きます。1つの表に追記する形だと、並行する PR が同じ場所を書き換えて必ずコンフリクトするためです。既存のファイルは書き換えません。

ファイル名は `<日付>-<その日の順番>-<issue番号>.md` です（例：`2026-09-25-03-42.md`）。

- 順番は、その日の記録のうち最も大きい番号に1を足した2桁の数です。並行するブランチで同じ番号になっても、issue番号が違えばファイルはぶつかりません
- issue のない作業では、issue番号の代わりに英小文字とハイフンの短い名前を使います（例：`2026-09-22-01-harness.md`）

中身は、先頭の `---` の間に5つの項目を1行ずつ書きます。値は `"` で囲みます。

```markdown
---
date: 2026-09-25
issue: "#42"
pr: "#75"
result: "業務日の切り替え検知（入力系の操作のたびに比べてダイアログ）"
next: "E2E は時刻を固定して 5:00 をまたぐ"
---
```

| 項目 | 内容 |
|---|---|
| `date` | 日付。ファイル名の日付と同じにする |
| `issue` | 対応した issue。なければ `-` |
| `pr` | PR。まだなければ `下記の PR` などの状態を書く |
| `result` | 結果。何を作り、何を決めたか |
| `next` | 次の予定・メモ。なければ `-` |

形式の誤りは `pnpm docs:check` が検出します。
